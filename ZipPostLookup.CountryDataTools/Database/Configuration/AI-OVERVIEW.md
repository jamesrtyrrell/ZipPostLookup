## Structural & duplication concerns
- This is the **single source of truth for the column maps** that the repositories' `BulkInsert`/`BulkMerge` calls depend on — but those same tables also have hand-written SQL in `CommonQueries.cs`. Column names (`ZpCode`, `PlaceName`, `Timezone`, `Flagged`, etc.) are therefore maintained in two unrelated files; a rename must be done in both or bulk paths silently diverge from query paths.
- Named mappings (`"NewReference"`, `"CoordUpdate"`, `"CandidateStatusOnly"`) are referenced by string literals from the import/enrichment handlers. These string keys are untyped magic strings with no compile-time link to their use sites — verify each named mapping still has a consumer (audit scope did not trace all of them).
- Mapping config lives in `Configuration/` while every other DB concern lives under `Database/`. Minor cohesion oddity — this is squarely a database-layer concern.

## Recommendations
- Consider relocating `DapperPlusConfiguration` under `Database/` (or `Database/Configuration/`) for cohesion.
- Define the named-mapping keys as `const string` and reference them from both registration and call sites to kill the magic strings.
- When adding/renaming a `data.Reference` column, treat this file and `CommonQueries.cs` as a paired edit.

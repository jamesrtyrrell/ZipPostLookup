# Models/Commands — AI Overview

_Generated by automated architecture audit. Snapshot of structure & concerns, not authoritative spec._

**Role:** Plain mutable counter / summary DTOs that command handlers fill during a run and then hand to a Display class for rendering. No DB mapping, no JSON.

## Files
| File | Responsibility | Notes / concerns |
|---|---|---|
| `ImportCounters.cs` | 11 `int` tallies for the importref pipeline (Processed, NewCodes, discrepancies, skips…). | Flat bag of setters; no behaviour. |
| `EnrichCandidateCounters.cs` | Enrich-candidate tallies + 3 dictionaries (`ResolvedByApi`, `DailyUsage`, `TransientByApi`) with increment helpers. | The only counter with logic. `DailyUsage` value tuple `(int Today, int? Limit)` overlaps `DataApiUsage` (Dbo). |
| `EnrichCoordinateCounters.cs` | 4 `int` tallies for coord enrichment. | Trivial. |
| `IntegrityCheckSummary.cs` | Immutable `record` snapshot (14 fields) of an integrity run, decoupled from the private `CheckResults` in the command. | Different shape/purpose from the three counters — leave separate. |

## Structural & duplication concerns
- Three *Counters types share the "mutable int tallies, reset per run, no behaviour" shape but have **no common base or interface**. They are not literally duplicate fields, so a shared base would be cosmetic only.
- `EnrichCandidateCounters` is the odd one out — it carries dictionaries + increment logic and crosses into API-usage tracking that also lives in `Dbo/DataApiUsage`. Worth noting the duplicated `(Today, Limit)` concept.
- `IntegrityCheckSummary` is correctly a `record` (immutable snapshot); the counters are correctly mutable classes. The split is justified.

## Recommendations
- Low priority. Do **not** force a shared counter base — the only real commonality is "ints incremented during a run", and a base adds indirection without removing code.
- If consolidating, consider a small `IRunCounters` marker only if a generic Display path emerges; today each has a bespoke Display method, so skip it.
- Note the `DailyUsage` ↔ `DataApiUsage` overlap when the Database agent reviews API-usage modelling.
